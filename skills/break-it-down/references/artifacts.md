# Artifact delivery

Read the section for the chosen medium. Discover the available production and verification tools before committing to a pipeline. Keep the requested inline or standalone surface and stack.

## Diagrams and interactive HTML

### Make the mechanism inspectable

Assign visual meaning before choosing components: which objects represent the subject, what a connection or axis means, and which changes reveal the rule. Use a labeled graph for relationships, spatial extent for scope, a timeline for order, or a worked calculation for quantities when those encodings fit. A table or prose may be the clearest representation for a lookup or distinction.

Let the main representation do explanatory work. An edge can show where information goes; a highlighted region can show which objects are included; intermediate values can show why an output changes. Put labels and qualifications beside the relevant part. Supporting prose supplies interpretation and evidence.

For interaction, specify the input, the affected model state, and the consequence the reader should inspect. Keep these connected in the visible representation. Where relationships or processes are the point, show the affected path, object, stage, or quantity as well as the verdict. When the question is purely a lookup, a text result can be sufficient.

Provide a useful initial case. Let the reader compare or return to states when that exposes a boundary or tradeoff. In a large manual, keep task lookup available alongside the conceptual explanation; preserve prerequisites, operational steps, and exceptions at their point of use.

### Compose and build

Organize the page around the selected representation and the reader's task. Choose hierarchy, layout, controls, and visual emphasis to support it. Expand dense material through focused views or supporting detail. Keep essential assumptions and conditions visible rather than hiding them solely in a glossary or disclosure.

Use an editable format such as Mermaid or SVG for exact diagrams, or an available illustration workflow for spatial detail and analogy. For standalone HTML with no specified stack, prefer a self-contained file with embedded styles, scripts, and required assets. Source links may remain external. An existing application should keep its established stack and requested design constraints.

Use real model logic for interactions. Label units and assumptions, distinguish hypothetical values, and preserve scope in every state. Keep controls accessible by keyboard with visible focus and meaningful names; encode state with more than color.

### Verify the actual output

- Render the diagram or open the HTML. Inspect labels, connections, contrast, and layout at the delivery size, including a narrow screen for a responsive page.
- Trace a representative case and a relevant contrasting or boundary case. Check that the representation exposes the reason for the difference and agrees with the source model. Do not count a changed heading, decorative motion, or a selected-button style as evidence that the model changed.
- Exercise primary controls, meaningful limits, and reset or reverse navigation where provided. Check keyboard access, runtime errors, and required assets. If offline use is promised, check that required resources are bundled.
- For a source-only request, validate the source and state which render or interaction checks remain undone. Preserve editable source or a generation brief for revision.

## Video and narrated animation

Design a sequence of visible reasoning: introduce an object or premise, apply a change, then show what follows. Maintain the identity of objects and terms across scenes. Motion, highlights, and narration should refer to the same part at the same time. A requested visual derivation needs its intermediate transformations, not only a sequence of text slides.

Draft each scene's idea, visual change, and spoken or captioned explanation. Keep conditions and limits attached to the relevant claim. For a script or storyboard request, finish and check that stage; any duration remains an estimate until measured.

For a finished video, use available animation, speech, and export tools. Produce requested narration, measure its duration, and align scene changes with the audio. For silent output, allow time to read and inspect the visuals. Add captions unless excluded by the request. Existing credentials alone do not authorize a new paid service.

Export a playable downloadable file for a generic finished-video request; use an HTML player when that surface was requested. Check actual playback, transitions, labels, duration, and format. Listen to included voice for timing and pronunciation. Verify decoding when a suitable tool is available, and test player controls when supplied.

Deliver editable scene or animation source alongside the result. If required audio or rendering is unavailable, identify the missing capability and label any intermediate result accurately.
