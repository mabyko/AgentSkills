# 조사 전후 지침의 같은 입력 비교

## 방법

- 날짜: 2026-10-27.
- 생성 모델: 두 별도 Claude Code 세션의 Claude Opus 5.5, effort=max, 제공자 Claude-dev-max.
- A: 공개 구현 조사 직전 지침. [본문](baseline/instructions.md), [언어](baseline/references/language.md), [매체](baseline/references/artifacts.md).
- B: 조사 후 재설계 지침. [본문](candidate/instructions.md), [언어](candidate/references/language.md), [매체](candidate/references/artifacts.md).
- 최종 차이: 생성 이후 소스 점검에서 이전 본문에 있던 출력 언어 우선순위(명시 요청 → 알려진 선호 → 요청 언어, 인용문 언어는 제외)를 언어 참조 첫 문단에 복원했다. 위 B 스냅샷에는 이 문장이 없으며, 그 문장 추가 후 모델 생성은 재실행하지 않았다. 본문의 798단어는 변하지 않았다.
- [동일 요청 전문](requests.md): C7~C10. 각 버전을 한 번씩 실행했다. 출력 생성 전에 판정 기준을 [사례 문서](../../../cases.md)에 기록했다.
- 생성 세션에는 지정 패킷과 요청만 주었다. 두 세션은 설치된 스킬·프로젝트 저장소·평가 기준·다른 패킷·이전 출력을 읽지 않았다고 보고했다. 이전 C2/C5/C6 실행의 설치 스킬 동시 로드 문제와 구분한다.
- 판정: 작성자가 실제 출력과 원자료를 대조했다. 같은 모델·옵션의 별도 생성이며, 독자 이해도 실험·통계적 비교·익명 전문가 평가는 아니다.
- 실행 입력 해시: [A](baseline-sha256.json), [B](candidate-sha256.json). 명세에는 읽지 않은 메타데이터도 포함된다. 위 스냅샷은 생성자가 읽었다고 보고한 지침 세 파일을 보존한다.
- 출력은 원본 파일을 바이트 그대로 복사했다. [길이와 출력 해시](metrics.json)는 기계적으로 계산했다. 지침 길이는 공백으로 나눈 단어 수이며 STE의 공식 단어 계산이 아니다.

C7은 두 버전 모두 아직 실제 앱에서 쓸 수 없다는 답을 먼저 줬다. 3.3 소스와 운영 중인 3.2, 로컬 테스트 6개와 예정된 스테이징 확인, 운영 반영 계획을 구별했다. 담당자와 반영 시각을 지어내지 않았고, 오타 수정을 다른 주체에게 귀속하지 않았다. 지금 사용자가 할 일도 없다고 했다.

C8은 두 버전 모두 이번 사건의 미확인 가설과 일반 가능성을 구별했고, `should`를 의무로 강화하지 않았다. 수행자가 없는 삭제는 수동문으로 두었다. 약 3일, 소유자 승인 전제, 승인해도 실패할 가능성을 유지했다. 식별자와 가상 명령은 바뀌지 않았고 명령을 실행하지 않았다. 영어 재작성 본문 외의 설명도 붙이지 않았다.

C9는 두 버전 모두 10 미만/이상 경계, 버튼을 누른 채 이동하는 동시 동작, 허용이라는 강도, 검토/승인의 차이를 보존했다. 자료에 원인이 없다는 진술을 실제 원인 불명으로 확대하지 않았고, 과정·과제·추가 예시를 붙이지 않았다.

C10은 두 버전 모두 토큰 분기, 접수/완료의 차이, 순차 처리, 성공 시에만 저장, 저장 실패 시 자동 재시도 없음이라는 조건을 보존했다. 실제 영상·음성 제작을 시작하지 않고 한국어 대본으로 마쳤다. 시간은 녹음 전 예상치로 표시했다. 실제 45초인지 측정하지 않았다.

## 무엇이 나아졌다고 말할 수 있는가

핵심 본문은 A 1,107단어에서 B 798단어로 약 28% 줄었다. 기본 응답 순서를 명시하고, 의미 보존·실제 사용 상태·형식 선택을 한 흐름으로 정리했다. 언어 참조에는 공식 구성 규칙과 양태의 범위 보존을 보강했다. 이는 소스에서 확인할 수 있는 변경이다.

두 참조 파일까지 포함하면 2,434→2,297단어로 약 6% 줄었다. 본문 감소율을 전체 컨텍스트·토큰·비용 절감률로 해석하지 않는다.

출력 길이는 일괄 감소하지 않았다. C7은 318→304자, C8은 432→413자, C9는 155→156자, C10은 1,208→1,418자였다. C10의 추가 분량은 주로 화면·장면 설명이다. 길이만으로 좋은 대본인지 판정하지 않았다.

이번 네 입력에서는 A도 이미 의미와 요청 범위를 보존했다. B가 모든 경우에 더 낫다는 결과는 아니다. 이번 실행이 뒷받침하는 것은 **지침을 정리한 뒤에도 이 네 사례의 의미 보존과 요청 범위를 유지했다**는 점이다. 실제 독자에게 더 빨리 이해되는지, 많은 실행에서 안정적으로 동작하는지는 측정하지 않았다.

## 검증 한계

버전당 네 요청을 같은 생성 세션에서 처리해 요청 사이의 영향을 분리하지 못했다. 각 버전의 단일 실행이므로 확률적 실패율은 추정할 수 없다. 생성자는 설치 스킬을 호출하지 않았다고 보고했지만, 이 기록은 공급자 런타임 전체의 숨은 지시를 감사한 결과가 아니다.

Markdown 화면 렌더링, 실제 HTML 상호작용·영상 재생, 정식 STE 사전 준수, 전역 설치본 갱신은 이 비교 실행에 포함되지 않는다. C1~C6 재실행 기록과도 구분한다. 최종 소스 리뷰는 이 표의 작성자 판정과 별도로 진행한다.

## 최종 Claude 리뷰와 반영

별도 Claude Opus 5.5(effort=max) 리뷰는 여덟 출력이 사례 기준을 충족한다고 판정했다. 차단할 문제는 없었고, 다음 두 가지 낮은 심각도 문구 수정을 요청했다.

- 원자료의 진술을 검증된 사실로 취급하지 않도록 본문의 `source facts`를 `source claims, verified results`로 바꿨다.
- 카파시는 형식을 글→그림→HTML→영상 순으로 더 낫다고 소개했다는 점과, 매번 상향하지 않고 필요한 형식을 고르는 것은 별도의 설계 판단이라는 점을 조사 문서에 명시했다.

선택적 정밀도 수정으로 description의 `result`를 복원하고, 정식 준수 절에서 수행자 불명일 **때만** 설명문 수동문을 허용한다고 명시했다. README의 어색한 한국어와 준수 용어도 맞췄다. 작은 문구 수정이므로 추가 위임 리뷰는 시작하지 않았다.

최종 본문은 801단어, 두 참조를 합친 지침은 2,323단어다. 비교용 B의 798/2,297단어와 구분한다. [최종 소스 해시](final-source-sha256.json)를 따로 기록했다. 위 언어 우선순위 복원과 리뷰 문구 수정 후에는 모델 출력을 새로 생성하지 않았으며, 최종 문구까지 재실행한 결과로 표를 해석하지 않는다.

리뷰는 C10의 화면 설명에도 작은 한계가 있음을 지적했다. A의 접수 응답 화면은 원자료가 정하지 않은 동시성을 표현했고, B는 요청 하나를 따라간다고 시작한 뒤 여러 카드 예시로 전환한다. 사례의 핵심 조건 위반으로 판정하지 않았지만, 실제 영상 제작 시에는 시간 관계와 객체의 연속성을 확인해야 한다. 원래 출력은 수정하지 않고 보존했다.

두 대본의 내레이션에서 한글 음절 블록만 세면 A 212, B 173이다. 전체 파일의 문자 수 증가는 녹음 길이 증가를 뜻하지 않는다. 이것 역시 녹음 시간 측정이 아니므로 정확한 45초나 전달 속도를 보증하지 않는다.
