# 45초 영상 대본: 요청은 어떻게 처리될까?

> 장면별 시간은 내레이션 약 210음절로 잡은 예상치입니다. 녹음한 뒤 실제 길이에 맞춰 장면 전환을 조정하세요.

### 1. 토큰 검사 (0:00–0:05)

**화면:** 요청 A와 요청 B가 왼쪽에서 들어와 '토큰 검사' 관문 앞에 선다.

**내레이션:** 요청이 들어오면, 시스템은 먼저 토큰을 검사합니다.

### 2. 거절 (0:05–0:09)

**화면:** 요청 B에 '토큰 무효' 표시가 붙고, B는 '거절' 쪽으로 빠진다.

**내레이션:** 토큰이 유효하지 않으면, 요청은 거절됩니다.

### 3. 대기열과 접수 응답 (0:09–0:21)

**화면:** 요청 A에 '토큰 유효' 표시가 붙고, A가 '대기열(처리를 기다리는 줄)'로 들어간다. 동시에 '접수 응답' 말풍선이 요청이 들어온 쪽으로 돌아간다. 말풍선 옆에 '접수 ≠ 처리 완료'가 뜨고, A는 대기열에 그대로 있다.

**내레이션:** 토큰이 유효하면 요청을 대기열에 넣고, 접수 응답을 보냅니다. 하지만 접수 응답은 요청이 접수됐다는 뜻이지, 처리가 끝났다는 뜻이 아닙니다.

### 4. 하나씩 처리 (0:21–0:31)

**화면:** 대기열의 요청이 한 번에 하나씩 '처리' 칸으로 들어간다. A가 처리 칸에 들어가면 출구가 '처리 성공 → 결과 저장'과 '처리 실패 → 저장 안 함' 두 갈래로 나뉜다. 내레이션에 맞춰 성공 갈래, 실패 갈래 순서로 강조한다. A는 성공 갈래로 나간다.

**내레이션:** 대기열에서는 요청을 하나씩 처리합니다. 처리에 성공한 경우에만 결과를 저장하고, 처리에 실패하면 저장하지 않습니다.

### 5. 저장 실패 (0:31–0:37)

**화면:** A가 '결과 저장' 칸에 닿는다. '만약 저장에 실패하면?' 자막과 함께 ✕가 뜬다. 옆에 나타난 '자동 재시도 ↻' 아이콘에 줄이 그어지고, '자동 재시도 없음'으로 바뀐다.

**내레이션:** 결과 저장에 실패하더라도, 시스템은 자동으로 재시도하지 않습니다.

### 6. 정리 (0:37–0:45)

**화면:** 거절 갈래와 저장 안 함 갈래까지 포함한 전체 흐름(토큰 검사 → 대기열 → 처리 → 결과 저장)이 한 화면에 보인다. '접수 ≠ 처리 완료'와 '자동 재시도 없음'이 차례로 강조된다.

**내레이션:** 정리하면, 접수 응답은 처리 완료가 아니고, 결과 저장에 실패해도 자동으로 재시도하지 않습니다.
