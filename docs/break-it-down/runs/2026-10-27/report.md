수집 담당자는 검색어를 46개에서 58개로 늘렸습니다. 기존 46개도 계속 수집합니다. 수집은 10월 24일 07:00 실행부터 시작하며, 첫 값은 색인 반영 전 기준선입니다. API 순위와 웹 순위는 JSON에만 기록하므로 대시보드에는 표시되지 않습니다. 시험 호출 1건은 정상 응답했지만, 이것만으로 전체 수집이나 검색 노출 효과를 확인한 것은 아닙니다.

## C5 최초 점검과 후속 정정 — 실패

원자료 첫 문장의 최종 판정 일정 대신 현재 상태를 먼저 제시했다. 수집 범위·시작·관측 위치를 한 묶음으로 연결하고 문서 정리와 운영팀의 확인 일정을 구분했다. 58개와 기존 46개 유지, 10월 24일 07:00, 기준선의 의미, JSON에만 기록하는 조건을 보존했다. 오타 수정은 문서 정리 뒤에 배치했다.

시험 호출과 효과 검증을 구별했고, 중간 확인의 한계와 최종 판정 예정도 유지했다. 사용자에게 새 과제를 만들지 않았다. 순위의 실제 값이나 검색 노출 효과를 지어내지 않았다. 최초 점검에서는 C5 판정 기준에서 누락을 찾지 못했다고 기록했다.

이 최초 판단은 잘못됐다. 원자료는 대시보드 제목의 오타를 누가 고쳤는지 명시하지 않는다. 응답은 이를 문서 담당자 단락에 넣어 문서 담당자가 고친 것처럼 읽히게 했다. 행위를 섞지 않는다는 기존 기준과, 행위자를 지어내지 않는다는 언어 지침을 충족하지 못했다. 시험 호출도 수행자 없이 수집 담당자 단락에 배치했다. 시험 호출 자체를 주어로 써서 오타 문장보다 귀속은 약하지만, 이 배치 역시 책임을 암시할 위험이 있다.

후속 수정에서는 제목·묶음·배치가 원자료에 없는 주체·상태·확실성을 암시하지 않도록 `SKILL.md`의 구성 단계와 추론 점검을 보강했다. 이 기록에는 수정 후 C5 재실행 결과를 추가하지 않았으며, 실패 응답을 수정 후 스킬의 출력이나 통과 증거로 사용하지 않는다.

## C6 응답

이 모델은 요청을 받을 때 저장된 결과를 계속 쓸지 확인합니다. 시간이 지났다는 이유만으로 원본을 다시 조회하지는 않습니다.

09:00에 처음 조회하면 결과와 조회 시각을 함께 저장합니다. 그 뒤 09:10까지 요청이 없었다면, 저장된 결과를 확인하거나 원본을 다시 조회하는 처리도 없었습니다. 그래서 10분을 기다려도 저장된 값은 그대로입니다.

09:10 이후 다음 요청이 들어오면, 그때 저장 후 얼마나 지났는지 계산합니다. 이미 600초 이상 지났으므로 원본을 다시 조회해 결과를 저장하고 저장 시각을 바꿉니다. 원본 값이 이전과 같다면, 다시 조회했어도 값 자체는 같을 수 있습니다.

이 판단의 경계는 300초입니다. 저장 후 300초 미만에 요청하면 저장된 결과를 사용합니다. 정확히 300초가 됐거나 더 지났다면 그 요청에서 원본을 다시 조회합니다. 09:05가 되어도 요청이 없다면 아무 처리도 일어나지 않습니다.

## C6 점검

요청이 판단을 시작한다는 규칙을 먼저 제시하고, 09:00 저장부터 요청 없이 09:10에 이른 상황을 설명한 뒤 다음 요청의 처리를 연결했다. 300초 경계와 요청 발생이라는 조건을 보존했고, 09:10 재조회를 실제 발생한 사건으로 쓰지 않았다. 재조회와 값의 변화를 구분했다.

역할별 보고나 사용자 과제를 붙이지 않았다. C5와 C6 모두 요청한 한국어 글로 완료했고 HTML·영상은 만들지 않았다. C6 판정 기준에서 누락을 찾지 못했다.
