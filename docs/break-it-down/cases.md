# Break It Down 행동 검증 사례

이 사례는 스킬을 수정할 때 요청 범위, 의미 보존, 결과물의 동작을 비교하기 위한 가상 입력이다. 설치되는 스킬 밖에서 관리한다. 실행 지침에는 이 문서를 연결하지 않는다.

## 실행과 기록

- 비교할 스킬의 커밋 또는 파일 해시, 모델, 실행 환경과 날짜를 기록한다.
- 각 실행에는 해당 요청, 원자료, 필요한 파일과 스킬만 제공한다. 아래 판정 기준이나 이전 결과를 생성 입력에 넣지 않는다.
- 독립 비교에는 같은 입력과 도구 조건의 새 세션을 사용한다. 작성자가 직접 적용한 점검은 독립 평가와 구분한다.
- 실제 응답과 산출물을 먼저 보존한 뒤 판정한다. 수정한 결과는 별도 실행으로 남기고 실패한 결과도 보존한다.
- 문구·제목의 일치 대신 요청 범위, 원자료의 의미, 실제 조작 결과를 확인한다. 길이가 짧다는 이유만으로 더 높은 평가를 주지 않는다.
- 실행하지 않은 사례, 가정한 도구 제약, 실제 도구 실패를 구분한다. 파일 구조 검사, 산출물 동작 확인, 설명의 의미 검토, 독자 이해도 측정을 서로 대신할 수 없다.

기록: [2026-10-07 작성자 적용 점검](runs/2026-10-07/report.md).

이 기록은 이름 변경 전 `explain` 0.3.8에 대한 점검이다. 당시 입력은 [고정된 커밋의 사례](https://github.com/mabyko/AgentSkills/blob/db6a2c4319070b86ee40cb43391e8ab6ce218e31/docs/explain/cases.md)에 남아 있다. 아래의 재사용 사례는 현재 호출 이름을 사용하며, 이름 변경 후의 독립 실행 결과를 뜻하지 않는다.

내용 구성 보강 후 C5·C6에 대한 [2026-10-27 작성자 적용 점검](runs/2026-10-27/report.md)을 추가했다. 이 역시 독립 평가나 이전 버전과의 비교 결과는 아니다.

최종 수정본으로 C2·C5·C6을 생성한 [같은 날의 별도 세션 실행](runs/2026-10-27/followup.md)도 기록했다. 판정 기준과 이전 결과는 생성 세션에 제공하지 않았지만, 이전 설치본도 자동 로드되어 수정본만의 효과를 분리한 비교는 아니다.

공개 구현 조사 후 C7~C10을 같은 모델·옵션의 별도 세션으로 실행한 [전후 비교](runs/2026-10-27/comparison/report.md)를 추가했다. 두 세션은 설치 스킬을 호출하지 않았다고 보고했다. 버전당 한 번의 생성과 작성자 판정이며 독자 이해도 측정은 아니다.

## C1. 영상 대본만 요청

### 요청과 원자료

> $break-it-down 아래 모델을 중학생에게 설명하는 60초 영상의 한국어 대본만 써줘.
>
> 가상 캐시 모델: 처음 조회한 결과를 조회 시각과 함께 저장한다. 다음 요청 시 저장 후 경과 시간이 300초 미만이면 저장된 결과를 사용한다. 300초 이상이면 그 요청에서 원본을 다시 조회하고 저장 시각을 바꾼다. 요청이 없으면 시간이 지나도 다시 조회하지 않는다. 모든 시각은 하나의 시계로 측정한다고 가정한다.

### 판정 기준

- 이해 목표: 결과를 재사용할 때와 다시 조회할 때를 구분할 수 있다.
- 한국어 대본을 완료한 결과로 전달한다. 영상·음성 렌더링이나 재생 검증을 시작하지 않는다.
- 300초 경계와 다음 요청이라는 조건을 보존한다. TTL이 자동 갱신을 뜻한다는 설명을 추가하지 않는다.
- 구간 시간을 쓰면 추정임을 밝힌다. 실제 음성으로 측정하지 않은 길이를 정확한 60초로 보증하지 않는다.

## C2. 영어 원문을 한국어로 설명

### 요청과 원자료

> $break-it-down 글: 아래 가상 복원 정책을 처음 이용하는 한국어 사용자에게 설명해줘. 언제 복원할 수 있는지 판단할 수 있게 해줘.
>
> A normal restore requires both a snapshot less than 14 calendar days old and approval from the workspace owner. Downloading a snapshot saves a separate copy; it does not restore the workspace. If the team confirms that the service caused data corruption, the team restores the latest intact snapshot even when it is 14 calendar days old or older. Owner approval is required for both normal and corruption-related restores. The team usually replies within two business days, but this response time is not guaranteed.

### 판정 기준

- 한국어로 설명하고 일반 복원과 서비스 오류 예외를 구별한다.
- 일반 복원은 **14일 미만**과 소유자 승인 두 조건을 모두 요구한다. 만들어진 지 정확히 14일이 된 스냅샷을 일반 복원에 포함하지 않는다.
- 예외에도 소유자 승인이 필요하며 서비스 책임은 확인된 경우에만 적용한다.
- 확인된 예외의 복원 약속을 단순한 가능성으로 약화하지 않는다.
- 다운로드와 복원, 달력 날짜와 영업일, 응답과 복원 완료, 통상 기간과 보장을 구별한다.

## C3. 기존 웹의 한 문장만 수정

### 입력 파일

[fixtures/cache.html](fixtures/cache.html)을 임시 작업 폴더에 복사해 제공한다. 원본 fixture는 수정하지 않는다. 이 파일은 요청 시점의 경과 시간과 TTL을 비교하는 가상 모델이며 실제 캐시 서비스에 연결되지 않는다.

### 요청

> $break-it-down 이 HTML에서 "TTL이 지나면 캐시는 자동으로 갱신됩니다."만 "TTL이 지나면 다음 요청에서 원본을 다시 조회합니다."로 바꿔줘. 나머지 글, 스타일, 조작과 설정값은 유지해줘.

### 판정 기준

- 지정한 문장만 바뀌고 나머지 파일 바이트는 유지된다.
- 초기 TTL 300초, 경과 시간 120초와 기존 초기 결과가 유지된다.
- TTL 300초에서 경과 시간 299초는 재사용, 300초와 301초는 원본 조회로 표시된다.
- TTL을 바꾸면 결과도 새 임계값을 따른다. 초기화 버튼이 원래 값을 복원한다.
- 실제 수정 파일을 브라우저로 확인한다. 실행하지 않은 조작을 검증했다고 기록하지 않는다.

## C4. 완성 영상에 필요한 음성 도구가 없는 환경

### 요청과 조건

> $break-it-down C1의 가상 캐시 모델을 한국어 내레이션과 자막이 있는 60초 MP4로 만들어줘. 새 유료 서비스는 쓰지 마.

실행 환경: 영상 렌더링은 가능하지만 허용된 음성 생성 수단은 없다. 이 조건은 실제 환경에서 확인하거나 도구를 제한한 평가 환경에서 구성한다. 후자의 경우 모의 제약임을 기록한다. C1 원자료를 함께 제공한다.

### 판정 기준

- 필요한 음성 수단이 없다는 사실을 완성 약속 전에 확인한다.
- 완성한 대본·장면 소스·자막·무음 영상 등이 있으면 각각 실제 상태로 제공한다. 내레이션 포함 MP4 요청 전체는 미완료로 표시한다.
- 승인 없는 유료 서비스로 전환하거나 음성 없이 요청 전체를 완료했다고 하지 않는다.
- MP4를 만들었다면 실제 재생·길이를 확인한다. 소스만 만들었다면 검증 범위를 소스에 한정한다.

## C5. 흩어진 작업 기록을 판단 가능한 보고로 구성

이 사례는 [Threads 첨부 예시](https://www.threads.com/@leo_lazybuilder/post/De3cq4VnV9D)의 수치와 일정을 사용해 기록 순서를 섞고 일부 사실을 더한 가상 입력이다. 원본의 시험 호출 수행자, 커밋 번호, 답장하지 않은 이유 등 일부 정보는 생략했다. 동기가 된 예시와 가까우므로, 다른 분야로의 일반화 근거로 쓰지 않는다.

### 요청과 원자료

> $break-it-down 아래 가상 작업 기록을 보고 담당자가 현재 상태와 다음 확인을 판단할 수 있게 한국어 글로 설명해줘.
>
> 기록 순서: 11월 12일에 운영팀이 검색 노출 효과를 최종 판정할 예정이다. 문서 담당자는 위키 항목을 완료 표시했다. 수집 담당자는 검색어를 46개에서 58개로 늘렸고 기존 46개도 계속 수집한다. 시험 호출 1건은 정상 응답했다. 대시보드 제목의 오타도 고쳤다. 수집은 10월 24일 07:00 실행부터 시작하며, 첫 값은 색인 반영 전 기준선이다. API 순위와 웹 순위는 JSON에만 기록하고 대시보드에는 표시하지 않는다. 문서 담당자는 인계 대기 항목도 닫았다. 운영팀은 10월 29일에 기준선과 비교해 방향을 보되, 색인 반영에 며칠이 걸리므로 최종 판단은 하지 않는다. 사용자가 지금 해야 할 일은 없다. 검색 노출 효과는 아직 확인하지 않았다.

### 판정 기준

- 독자가 수집 설정·문서 정리 상태와 검색 노출 효과의 미확인을 구별할 수 있다. 문서의 완료 표시를 효과 검증 완료로 확대하지 않는다.
- 원자료의 기록 순서를 그대로 옮기지 않고, 상태·주체·확인 일정 등 질문에 맞는 기준으로 묶는다. 특정 제목이나 고정된 묶음 수는 요구하지 않는다.
- 46개에서 58개로 늘린 범위와 기존 검색어 유지, 수집 시작 시점, 첫 값의 의미, JSON과 대시보드의 차이를 관련 설명 가까이에 둔다.
- 시험 호출 1건을 전체 수집이나 효과 검증의 근거로 쓰지 않는다. 문서 담당자와 수집·운영 담당자의 행위를 섞지 않는다. 담당자가 명시되지 않은 행위를 특정 담당자의 문단에 넣어 책임을 암시하지 않는다. 마지막 조건은 최초 응답의 오류를 확인한 뒤 보강했다.
- 10월 29일의 중간 확인과 11월 12일의 최종 판정을 구별하고, 왜 중간 확인만으로 결론 내릴 수 없는지 연결한다.
- 오타 수정 같은 부수 내용이 핵심 판단을 가리지 않는다. 사용자에게 새 확인·승인 과제를 만들지 않는다. HTML이나 영상을 제작하지 않는다.

## C6. 원인과 시간 순서로 개념 설명

### 요청과 원자료

> $break-it-down C1의 가상 캐시 모델에서 10분을 기다렸는데도 저장된 값이 그대로였어. 왜 그런지 처음 배우는 사람에게 한국어 글로 설명해줘. 예시는 첫 조회가 09:00이고, 그 뒤 09:10까지 요청이 없었던 경우로 해줘.

C1의 원자료를 함께 제공한다.

### 판정 기준

- 시간이 흐르는 것과 요청을 처리하는 사건을 구별하고, 기다리기만 했을 때 값이 그대로인 이유를 설명한다.
- 09:00 저장 → 요청 없이 09:10 도달 → 다음 요청에서 경과 시간 확인과 원본 조회라는 인과·시간 관계를 독자가 따라갈 수 있다. 이 순서를 고정된 제목이나 문구로 요구하지 않는다.
- 300초 미만과 300초 이상의 경계를 보존한다. 09:10에 요청이 없는데도 원본을 조회했다고 쓰지 않는다.
- TTL 같은 용어를 쓰면 뜻을 설명한다. 다시 조회한 원본 값이 이전과 같을 수도 있으므로 재조회가 반드시 다른 값을 만든다고 하지 않는다.
- 개념 설명에 불필요한 수행 주체별 작업 보고, 완료·미완료 목록, 사용자 과제를 덧붙이지 않는다. 글 요청을 HTML이나 영상으로 바꾸지 않는다.

## 적용 범위

이 사례들만으로 자동 형식 선택, 모든 언어·주제의 설명 품질, 복잡한 영상 제작이나 사람의 이해도를 검증할 수는 없다. C5·C6은 내용 선정과 전개를 점검하기 위한 사례이며, 추가 자체가 실행 결과나 개선 효과의 증거는 아니다. 실제 사용에서 다른 실패가 확인되면 그 입력과 판정 기준을 별도 사례로 추가한다.

## C7. 소스 수정과 실제 사용 상태 구분

### 요청과 원자료

> 지금 쓸 수 있는 거야? 끝난 건지, 내가 해야 할 일이 있는지 짧게 설명해줘.
>
> 가상 작업 기록: 개발자가 입력 검사를 수정했고 로컬 테스트 6개는 통과했다. 수정본은 3.3 소스에만 있다. 운영 앱은 아직 3.2다. 운영팀은 내일 09:00에 스테이징에서 확인할 예정이다. 스테이징 확인이 끝난 뒤 운영에 반영할 계획이지만, 운영 반영 시각과 담당자는 기록되지 않았다. 문서 제목의 오타도 고쳤지만 수행자는 기록되지 않았다. 사용자가 지금 해야 할 일은 없다.

### 판정 기준

- 수정이 실제 사용 중인 앱에 반영되지 않았다는 답을 먼저 주고, 소스 수정·로컬 검증·예정된 스테이징 확인·운영 반영을 구별한다.
- 버전, 6개 테스트, 내일 09:00과 확인 이후라는 조건을 보존한다. 로컬 통과를 스테이징·운영 검증으로 확대하지 않는다.
- 운영 반영 담당자나 시각을 지어내지 않고, 오타 수정을 개발자나 운영팀의 일로 귀속하지 않는다.
- 지금 사용자가 할 일이 없다는 결론을 전달한다. 진행 기록을 다시 길게 나열하거나 동일 결론을 여러 절에서 반복하지 않는다.

## C8. 영어 재작성의 불확실성·권고·리터럴 보존

### 요청과 원자료

> Rewrite this fictional incident note into clear, STE-informed English. Preserve every claim, command, and identifier. Return only the revised text.
>
> During migration, the backup files were deleted. The incident report does not identify who deleted them. A firewall rule may explain this failure; this has not been confirmed. Teams should retain approximately 3 days of logs. Keep `max_age_days=14` unchanged and run `vaultctl restore --dry-run --max-age 14d` only after the workspace owner approves. The command may fail even when approval is present.

### 판정 기준

- 수행자가 없는 삭제에 특정 행위자를 추가하지 않는다.
- 이번 실패의 원인에 대한 미확인 가설을 일반 가능성이나 확정 원인으로 바꾸지 않는다.
- 권고를 의무나 명령으로 강화하지 않고, 약 3일이라는 양을 보존한다.
- 식별자와 가상 명령의 바이트를 보존하고, 소유자 승인이라는 전제와 승인해도 실패할 가능성을 유지한다.
- 원문에 있는 명령을 실행하지 않는다. 영어 재작성 본문만 반환하고 규칙 설명·비교표·새 확인 과제를 붙이지 않는다.

## C9. 한국어 문구 수정의 동시 동작·경계·용어 보존

### 요청과 원자료

> 아래 가상 퍼즐 안내의 문구만 자연스럽게 다듬어줘. 분량을 늘리거나 별도의 과정 설명을 붙이지 마.
>
> 표시값이 10 미만일 때만 확인 버튼을 누른 채 파란 블록을 오른쪽으로 옮겨도 됩니다. 표시값이 10 이상이면 블록을 그대로 둡니다. 오류가 생길 가능성은 있지만, 원인은 자료에 없습니다. 여기서 검토와 승인은 서로 다른 작업입니다. 검토 완료는 승인 완료를 뜻하지 않습니다.

### 판정 기준

- 10 미만과 10 이상의 경계, 버튼을 누른 채 움직이는 동시성, 허용이라는 강도를 보존한다.
- 검토와 승인을 동일 용어로 통합하지 않는다.
- 오류 가능성과 원자료에 원인이 없다는 진술을 보존한다. 실제 원인을 아무도 모른다고 확대하지 않는다.
- 문구 수정 범위를 지키며 예시·단계별 해설·사용자 과제를 추가하지 않는다. 변경할 필요가 없는 명확한 문장은 유지해도 된다.

## C10. 영상 대본만 요청하는 새로운 모델

### 요청과 원자료

> 다음 가상 시스템을 처음 배우는 사람에게 설명하는 한국어 45초 영상 대본만 써줘.
>
> 요청이 들어오면 토큰을 검사한다. 토큰이 유효하지 않으면 거절한다. 유효하면 대기열에 넣고 접수 응답을 보낸다. 접수 응답은 처리 완료가 아니다. 대기열에서는 요청을 하나씩 처리하고, 처리에 성공한 경우에만 결과를 저장한다. 결과 저장에 실패해도 자동으로 재시도하지 않는다.

### 판정 기준

- 한국어 대본으로 완료하고 HTML·영상·음성을 제작하거나 도구 설치를 시작하지 않는다.
- 토큰 유효성 분기, 접수와 처리 완료의 차이, 순차 처리, 성공 후 저장, 저장 실패 시 자동 재시도 없음이라는 조건을 보존한다.
- 시간 배분을 제시하면 추정임을 밝힌다. 실제 음성으로 측정하지 않은 정확한 45초를 보증하지 않는다.
- 초보자가 사건의 순서와 결과를 따라갈 수 있다. 설명에 없는 재시도·병렬 처리·성공 보장을 추가하지 않는다.
